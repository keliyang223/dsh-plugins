# DSH File Write

[English](README.en.md)

DeepSeek Harness Web `0.1.7-rc.1` 的独立插件：在右侧文件预览中编辑文本，并在文件树中右键新建或删除文件。

## 用法

- 打开 `.md`、`.markdown` 文件并留在原生 **Markdown** 模式后，会直接进入排版编辑；可选中文字或段落，使用 **H1**、**H2**、粗体、斜体、代码和无序列表按钮格式化。停止输入约 600 毫秒后自动保存，编辑框和光标保持原位。点击 **返回预览** 时刷新渲染结果，尚未保存的修改会确认并暂存草稿。
- 其他文本文件仍可在预览的查看方式中选 **编辑源文件**，输入后自动保存；Markdown 也保留这一备选视图。
- 在文件树中右键**目录**，可选 **新建文件**（输入单个文件名，如 `a.md`）或 **删除文件**；右键**普通文件**只提供 **删除文件**，不提供新建文件。文件树空白区域不提供增删操作。目录删除会递归删除其中所有内容，操作前须在确认弹窗中确认，且无法撤销。
- 与 `dsh-file-to-chat` 同时安装时，增删操作会加入同一个右键菜单；单独安装也可使用。

## 安装

```sh
dsh plugin --profile web add "/absolute/path/to/dsh-plugins/dsh-file-write"
```

重启当前 DSH Web 进程并刷新页面，使宿主写入服务和浏览器端编辑器生效。卸载：`dsh plugin --profile web remove dsh-file-write`。

## 安全与限制

- 仅写入当前活动会话工作区内的普通文本文件，不创建文件夹；尊重会话只读策略。文件名只能是单个名称，不能包含 `/`、`\` 或路径穿越。
- 新建文件使用“仅在不存在时创建”，不会覆盖同名文件；保存需要打开时的文件版本，发现其他程序修改后拒绝覆盖并保留草稿。
- 编辑仅支持 UTF-8 且不含 NUL 的文件，原文件与写入文本上限为 2 MiB。大文件、非文本内容和权限不足均不能保存。
- 编辑区只在完整内容及版本读取成功后启用。输入停止约 600 毫秒后自动保存；写入失败或版本冲突时保留草稿并停止重试，继续编辑后才再次尝试。草稿仅在当前页面生命周期内暂存，刷新或关闭页面前请确认显示“已保存”，否则请先复制草稿。冲突不会自动合并。
- 增删操作经 DSH 宿主端检查会话与工作区；只读会话禁止删除；不能删除工作区根目录或符号链接本身，越界目标会拒绝。删除使用本地 Node 文件系统（当前 DSH 文件系统接口不提供删除原语），会在删除前重新检查路径；如果有恶意进程同时替换祖先目录的符号链接，底层缺少无竞争条件的目录句柄删除原语，仍存在 TOCTOU 风险。请勿在不可信的并发修改环境中使用递归删除。

## 开发

```sh
npm run build
npm test
```

`lib/index.js` 是宿主端的受控写入服务；`lib/client.js` 注册文本编辑视图和新建文件菜单。`cordis.patch.yml` 把两端加入 Web profile。
